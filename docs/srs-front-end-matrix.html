SRS Mapping

SkillGap.AI — Matriks Pemetaan SRS vs Front-End

Dokumen ini menjelaskan bagaimana kebutuhan fungsional utama pada SRS diterjemahkan ke dalam komponen front-end berbasis TypeScript, pola lokal, serta validasi runtime dengan Zod.

Kode Kebutuhan SRS Implementasi Front-End Validasi & Tipe
FR-01 Pengguna dapat mendaftar dan masuk ke sistem. Form register/login berdasarkan pola komponen dan UI state lokal. zod schema, z.infer, strict TS
FR-02 Pengguna dapat menjalankan assessment dan melihat hasil rekomendasi. Form assessment dengan event delegation dan status async. idle | loading | success | error discriminated union
FR-03 Dashboard menampilkan profil dan data pengguna. Card KPI, tabel profil, dan list order/sertifikat. Branded IDs: StudentId, ProductId
FR-04 Sistem menyediakan lisensi dan sertifikat. Komponen card sertifikat dan transaksi lisensi. Domain model pada Certification dan OrderSummary
FR-05 Data harus terstruktur dan aman dari input tidak valid. Semua input diproses dengan runtime guards dan validasi form. strict: true, noUncheckedIndexedAccess: true
FR-06 Antarmuka harus responsif dan konsisten. Komponen lokal seperti Button, Badge, Card menggunakan CVA. Reusable local component pattern dengan controlled variance.

Catatan implementasi: Keberhasilan front-end didukung oleh konfigurasi TypeScript ketat, model status terdistribusi, validasi runtime Zod, serta branded domain identifiers untuk menjaga konsistensi data antarmuka.
